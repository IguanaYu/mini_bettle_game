# xixuegui1010 游戏功能设计文档

初版功能范围与攻击特效研究

版本：V0.1　日期：2026年10月10日　项目：xixuegui1010

本项目以《吸血鬼幸存者》的核心玩法为参考，制作一个俯视视角的 2D 生存原型，用于学习攻击特效、弹道和命中反馈。开发首先完成五分钟的生存循环和一种火球攻击，再加入可控制条件的特效试验模式，随后逐步扩展闪电和水系攻击。本文用于指导首轮开发、功能验收和后续实验。

项目方向来自本次讨论。操作方式、数值、界面布局和实现组织是本版提出的设计基线；数值均为首轮测试建议值，不是原作数据，也不代表已经完成平衡验证。首版优先验证功能与研究流程，最终美术风格和正式发行范围在后续版本确定。

## 1 项目定位与设计目标

### 1.1 项目定位

玩家控制角色在开放场地移动，敌人持续从视野外出现并追赶角色。角色按固定间隔自动攻击附近敌人，击杀后掉落经验，拾取经验后升级并选择强化。玩家在不断增强攻击能力的过程中维持生存。

原型同时承担特效试验场的作用。每一种攻击都能在固定靶场中单独观察，也能放到正常生存流程里检验连续攻击、多个目标和高密度画面的表现。

### 1.2 学习目标

- 理解攻击从准备、发射、飞行、命中到消散的完整时间节奏。
- 用轮廓、运动和残留表现区分元素，逐步形成自己的视觉设计经验。
- 比较单次攻击和密集攻击的表现，观察方向、命中与危险信息是否清楚。
- 分开管理攻击规则与视觉表现，让同一规则可以替换不同特效版本。
- 保存实验条件、观察和结论，为以后制作 RTS、RPG 或横版探索游戏积累方法。

### 1.3 首版完成标准

首版完成时，玩家能开始一局游戏，移动、自动攻击、击杀、拾取经验和选择升级，最终死亡或生存满五分钟，并能再次开始。开发者可以进入固定靶场，反复触发火球攻击、切换两个视觉版本并观察命中全过程。

后续复用的重点是设计经验、参数组织和制作方法。成品特效进入不同视角、镜头距离或战斗密度的游戏时，仍需重新调整尺寸、亮度、持续时间和信息优先级。

## 2 版本范围与开发顺序

### 2.1 功能优先级

P0 为 V0.1 的必需功能。P1 为完成首版后的元素扩展。P2 为未来有实际研究需要时再安排的功能。

| 优先级 | 功能范围 | 完成目的 |
| --- | --- | --- |
| P0 | 一张开放地图、一个角色、一类追击敌人 | 建立最小战斗场景 |
| P0 | 一种火球、生命、经验、升级、五分钟结算 | 完成生存循环 |
| P0 | 单靶与固定靶群、单次触发、暂停、慢放、参数调整 | 支持控制条件的观察 |
| P0 | 火球视觉 A 和 B、实战快速测试、实验记录 | 完成第一次特效比较 |
| P1 | 连锁闪电与水波、独立参数、组合测试 | 扩展表现方式与攻击规则 |
| P1 | 试验预设导入导出、声音版本、更多弹道 | 提高反复实验的效率 |
| P2 | 更多角色、敌人技能、局外成长、武器进化、地图内容 | 按后续研究需求扩展 |

### 2.2 首版内容规模

场景采用俯视 2D 表现。首版建议使用 Windows 桌面键盘操作，设计视口为 1280 × 720，允许窗口缩放并保持宽高比。地图先使用简单地面和清晰的角色轮廓；玩家、敌人和经验物也可使用占位图形。

首版只有一种攻击规则。火球的 A、B 版本是同一攻击的两套视觉表现，共享伤害、速度、碰撞范围和命中时刻。闪电、水波和更丰富的弹道放在 P1，以便首轮先把实验方法建立起来。

### 2.3 开发顺序

先完成移动、刷怪和命中，再补全经验、升级与结算。随后完成固定靶场和火球 A/B 比较。每增加一种元素，先在靶场验证完整攻击，再进入生存模式测试密集场景，最后记录结论。

## 3 核心流程与游戏状态

### 3.1 一局游戏的流程

开始游戏 → 角色移动 → 敌人进入场地 → 自动攻击 → 命中与击杀 → 拾取经验 → 升级选择 → 返回战斗 → 死亡或完成五分钟 → 结算 → 重开或返回主菜单。

倒计时只在正常战斗时推进。暂停和升级选择期间，敌人、攻击、经验吸取、刷怪计时与游戏倒计时一起停止。恢复时继续原状态，不集中补发暂停期间的攻击或刷怪。

### 3.2 状态定义

| 状态 | 允许的操作 | 进入与离开条件 |
| --- | --- | --- |
| 主菜单 | 开始生存、进入试验模式、退出 | 启动游戏或返回菜单 |
| 生存中 | 移动、打开暂停 | 开始一局或恢复战斗 |
| 升级选择 | 选择一项强化 | 经验达到阈值；处理完全部待升级次数后恢复 |
| 暂停 | 继续、重开、返回菜单 | 按 Esc 或点击暂停按钮 |
| 结算 | 重开、返回菜单 | 玩家生命为零，或生存时间达到 300 秒 |
| 特效试验 | 配置条件、单次触发、连续触发、观察 | 从主菜单进入；退出时返回主菜单 |

同一帧既触发玩家死亡又达到 300 秒时，以死亡结算。结算生成后停止世界更新，本局结果只生成一次。重开必须清除上一局敌人、弹体、经验、特效、计时器、待升级次数和统计数据。

## 4 玩家与地图

### 4.1 移动与镜头

WASD 和方向键控制移动，支持八方向。斜向移动速度与水平移动相同。无输入时立即停止；首版不增加惯性，以便直接观察攻击与走位。

摄像机跟随玩家，背景随世界坐标连续铺展。场地不设置障碍物或边界阻挡。敌人的刷新位置使用镜头显示范围确定；可选镜头震动只影响显示，不改变碰撞、瞄准和刷怪位置。

### 4.2 玩家基础参数

本文中的 px 指设计视口对应的世界像素单位。窗口缩放只改变显示大小，不改变世界参数。

| 参数 | 建议初始值 | 规则 |
| --- | --- | --- |
| 最大生命 | 100 | 当前生命初始等于最大生命 |
| 移动速度 | 220 px/s | 八方向归一化 |
| 身体碰撞半径 | 12 px | 用于与敌人接触判定 |
| 接触伤害后的无敌时间 | 0.6 s | 同时接触多个敌人只接受一次伤害 |
| 经验拾取半径 | 50 px | 进入范围后开始吸向玩家 |

### 4.3 受伤与死亡

玩家有效受伤时扣除生命，显示短暂受击闪白并播放一个受击音。无敌期间用低频透明度变化表示状态。首版镜头震动默认关闭，可在研究阶段单独开启比较。

当前生命降到零时停止玩家移动与攻击，进入结算。无敌选项只属于试验模式，开启后不扣生命；该状态在界面持续标明。

## 5 敌人与刷怪

### 5.1 敌人行为

首版敌人只追赶玩家，不拥有远程攻击或独立技能。敌人持续朝玩家当前位置移动；与玩家接触时尝试造成伤害，实际扣血受玩家无敌时间限制。

敌人生命、追击速度、接触伤害和掉落量独立配置。普通敌人的轮廓和颜色应与玩家区分，受击闪白时间较短，死亡后迅速撤销碰撞并播放简短消散效果。

| 参数 | 建议初始值 | 规则 |
| --- | --- | --- |
| 最大生命 | 30 | 每个敌人独立记录 |
| 身体碰撞半径 | 12 px | 接触判定使用 |
| 接触伤害 | 10 | 不绕过玩家无敌时间 |
| 经验掉落 | 5 | 每次有效死亡只生成一次 |
| 受击闪白 | 0.08 s | 只改变显示 |
| 死亡消散 | 0.18 s | 开始死亡时即撤销伤害与碰撞 |

### 5.2 刷怪节奏

以下是五分钟原型的建议曲线。刷新间隔和上限控制场景压力，首轮实测后调整。

| 生存时间 | 每次刷新间隔 | 同时存活上限 | 追击速度 |
| --- | --- | --- | --- |
| 0 至不足 60 s | 1.3 s | 60 | 80 px/s |
| 60 至不足 180 s | 0.8 s | 100 | 90 px/s |
| 180 至 300 s | 0.5 s | 150 | 100 px/s |

每次刷新一个敌人，从镜头四边之外至少 64 px 的位置出现。达到存活上限时跳过本次刷新，不累积欠账；空出名额后按照下一个正常刷新时刻继续。敌人移动超过玩家 1700 px 时直接回收，不产生击杀统计和经验。

首版允许敌人局部重叠，先保证追击和伤害逻辑清楚。若重叠使画面难以观察，再增加轻量分离行为；该调整作为独立实验记录。

### 5.3 死亡的唯一处理

同一敌人在同一帧受到多次伤害时，可以分别结算有效命中，但死亡、掉落和击杀计数只执行一次。已死亡或已回收的目标不再接受后续攻击伤害。

## 6 火球攻击与受击反馈

### 6.1 自动攻击规则

攻击间隔到达时，在玩家 900 px 范围内寻找最近的存活敌人。首版不设置蓄力等待；视觉发射闪光与实际生成弹体发生在同一时刻。若之后添加会延迟弹体生成的前摇，应单独修改攻击规则并记录，不能只通过特效暗中延迟伤害。

火球朝发射时目标的位置直线飞行，发射后不追踪。两个目标距离相同时用稳定的生成序号决定目标。没有有效目标时不生成火球，并进入下一次正常攻击间隔。火球碰到第一个敌人后造成伤害、触发命中表现并销毁。

### 6.2 火球规则参数

| 参数 | 建议初始值 | 说明 |
| --- | --- | --- |
| 发射间隔 | 1.0 s | 攻速升级会缩短间隔 |
| 瞄准范围 | 900 px | 按玩家至敌人中心距离计算 |
| 飞行速度 | 480 px/s | 恒定直线移动 |
| 伤害 | 20 | 首版无暴击与元素抗性 |
| 碰撞半径 | 8 px | 与可见主体大小分开配置 |
| 最长存活时间 | 2.0 s | 到时消散，不触发命中伤害 |
| 穿透数量 | 0 | 首次有效命中后结束 |

弹体必须对本帧移动路径进行连续命中检测，防止速度较高或帧率下降时穿过敌人。检测到多个交点时，先处理沿飞行路径最早的交点。

初始敌人生命为 30，初始火球伤害为 20，因此通常需要两发命中才能击杀。这个关系便于观察第一次受击与第二次死亡反馈，后续平衡调整允许改变。

### 6.3 火球视觉 A 和 B

两种视觉共享全部规则参数，不增加额外伤害。A 使用清晰主体、短尾迹和紧凑命中闪光作为比较基线；B 增加轮廓翻卷、尾迹变化与余烬，观察元素性格是否增强，以及连续发射时是否过于遮挡。

| 视觉环节 | A 版起始建议 | B 版起始建议 |
| --- | --- | --- |
| 发射闪光 | 0.06 s，紧贴发射点 | 0.08 s，加入向外碎片 |
| 可见主体半径 | 10 px | 10 px，轮廓动态变形 |
| 尾迹寿命 | 0.12 s | 0.22 s |
| 命中主体 | 0.18 s，最大半径 24 px | 0.26 s，最大半径 28 px |
| 余烬 | 0.15 s | 0.35 s |

这些数值只用于首次比较。视觉爆开不产生范围伤害，碰撞半径显示工具可以帮助判断玩家是否误以为存在爆炸范围。若实验表明误读明显，应缩小表现，或将范围伤害作为新的攻击规则另行设计。

### 6.4 命中和反馈的时序

检测到命中后立即结算伤害，再触发命中闪光、敌人受击和声音。死亡敌人只进入一次死亡流程。火球未命中而到期时，播放较轻的消散，避免产生与命中相同的反馈。

首版提供发射、命中、击杀和玩家受击的基础声音。火球 A/B 首轮比较使用相同声音；需要比较声音时再单独更换。高频命中声音设置同类播放间隔，避免同一瞬间过多叠加。

## 7 经验与升级

### 7.1 经验拾取

敌人死亡后在原位置生成一个价值为 5 的经验物。经验物落地后保持静止；玩家进入拾取半径时，经验物以建议 420 px/s 向玩家移动。已开始吸取的经验物继续追随玩家，接触玩家后只增加一次经验并销毁。

暂停、升级和结算状态停止经验物运动。首版不设置掉落经验的消失时间。为防长时间测试持续积累对象，可合并彼此接近的经验物，合并前后总经验价值必须相等。

### 7.2 升级阈值与连续升级

玩家从等级 1 开始。当前等级为 L 时，下一次升级所需经验为 20 + 10 × (L − 1)。例如从等级 1 升至 2 需要 20，升至 3 再需要 30。达到阈值时扣除对应经验，剩余经验保留。

一次拾取跨过多个升级阈值时，逐次显示升级选择。只有全部待升级次数处理完后才恢复战斗。选择期间不移动、不受伤、不继续刷怪。

### 7.3 强化选项

从仍可升级的条目中随机抽取最多三个不同选项。可用条目不足三个时显示实际数量，不重复同一条目。

| 强化 | 每次效果 | 最大次数 |
| --- | --- | --- |
| 火球伤害 | 增加 5 | 5 |
| 火球攻速 | 当前发射间隔乘 0.9 | 5，间隔不低于 0.55 s |
| 移动速度 | 增加 10 px/s | 5 |
| 经验拾取范围 | 半径增加 20 px | 5 |
| 最大生命 | 上限增加 10，同时恢复 10 | 5 |

所有强化达到上限后，后续升级直接恢复最多 25 点生命，不显示选择界面。满生命时恢复量为零，等级和经验处理仍正常完成。选择卡片显示本次实际变化，例如“火球伤害 20 → 25”，方便判断升级效果。

## 8 界面与操作

### 8.1 主要界面

主菜单提供“开始生存”“特效试验”“退出”。生存界面显示当前与最大生命、等级、经验进度、剩余时间、击杀数及火球当前等级信息。信息放在屏幕边缘，尽量保持玩家周围清楚。

升级界面暂停世界并显示最多三个强化卡片，支持鼠标点击和数字键选择。暂停界面提供继续、重开和返回菜单。结算界面显示胜负原因、生存时间、击杀数、最终等级和已选强化，提供重开与返回菜单。

### 8.2 操作约定

| 操作 | 生存模式 | 试验模式 |
| --- | --- | --- |
| WASD 或方向键 | 移动角色 | 移动角色，可锁定角色位置 |
| Esc | 打开或关闭暂停 | 打开退出与重置菜单 |
| 数字键 1 至 3 | 升级界面选择对应卡片 | 不作为全局快捷键 |
| 空格 | 无额外战斗动作 | 世界运行时触发一次攻击 |
| 界面按钮 | 开始、选择、重开 | 切换视觉、触发、暂停、慢放、重置 |

试验暂停时，单次触发按钮和空格不生成攻击，界面提示先恢复或开启慢放。输入数值框拥有焦点时，不触发移动和攻击快捷键。退出试验或重开生存后，时间倍率恢复为 1，试验无敌和固定靶场设置不带入正常游戏。

## 9 特效试验模式

### 9.1 场景预设

固定靶场和实战追击共用攻击规则，但拥有独立的生命、掉落与生成配置。

| 预设 | 场景条件 | 主要观察 |
| --- | --- | --- |
| 单靶观察 | 一个静止靶，固定发射点，命中后立即恢复靶生命 | 主体、尾迹、命中时刻 |
| 固定靶群 | 靶子按固定圆环或网格排列，建议 10 至 50 个 | 方向、范围与多个命中效果 |
| 实战追击 | 使用生存刷怪规则，可开启无敌并指定敌人上限 | 连续攻击、走位、视觉密度 |

固定靶场不掉经验、不升级、不统计正式生存结果。靶子的生命恢复发生在本次伤害结算之后，每次命中仍可产生受击反馈。攻击引用本次攻击编号，靶子生命恢复不能使同一攻击再次命中同一目标。

### 9.2 试验控制

P0 提供单次触发、连续自动触发、世界暂停、0.25 倍慢放和 1 倍播放。暂停与慢放只控制世界模拟；面板始终能够点击和输入。界面同时显示游戏时间与真实经过时间，便于理解慢放条件。

参数面板区分“攻击规则”和“视觉表现”。规则参数包括伤害、间隔、速度、寿命和碰撞半径；视觉参数包括主体尺寸、尾迹寿命、命中尺寸、消散时间和亮度。调整规则时明确标出本轮已改变玩法条件。

### 9.3 切换视觉与重置

切换 A/B 时只影响之后生成的攻击。已经生成的弹体和命中特效保留原版本直到结束，避免改变中途表现。需要干净比较时，使用重置清空场景后再次触发。

重置清除敌人、攻击、特效残留、经验、伤害记录和全部计时，恢复选定预设，并按当前随机种子初始化。固定靶场在相同条件下重复观察；实战模式的随机种子只固定随机生成的起点，不承诺不同操作和帧率下产生完全相同的战斗过程。

### 9.4 可读性辅助

P0 提供深浅背景切换、灰度显示和碰撞范围显示。灰度显示同时作用于所有攻击，帮助检查元素是否依靠运动和轮廓区分。碰撞范围是开发者辅助信息，只在试验模式显示。

界面显示当前敌人数、弹体数、活跃特效数、帧率与帧时间。面板可以收起；收起后仍显示暂停、播放倍率和无敌状态，避免误判测试条件。

## 10 元素扩展与视觉原则

### 10.1 元素表现方向

火焰可以采用翻卷、破碎、膨胀和余烬表现热量与躁动。闪电可以采用折线、分叉和短促闪光表现突然放电。水可以采用拉长、压扁、泼洒和涟漪表现流动与重量。这些是实验起点，具体效果由观察结果决定。

研究元素外观时，先让三个视觉版本共享同一条直线弹道与命中规则。研究不同攻击方式时，再分别加入连锁和波面扩散。两类实验分别记录，避免把攻击规则变化误归因于美术表现。

### 10.2 连锁闪电建议规则

P1 闪电每 1.5 秒寻找 900 px 范围内最近的敌人作为首个目标，再依次寻找上一个目标 180 px 内最近且尚未命中的目标，最多命中三个。每段造成 15 点伤害，相邻段相隔 0.08 秒。目标列表在发射时确定。

段触发时对应目标若已死亡或回收，跳过该段伤害，也不重新搜寻目标。连接使用该段触发时有效目标的位置；无有效目标则不显示该段，后续有效段可从最近一个有效节点继续。每个目标每次闪电只受伤一次。

初始视觉建议为 0.10 秒主闪光和 0.18 秒余光。视觉持续时间与伤害时刻分开配置，拉长余光不会增加伤害次数。优先观察连接顺序能否读懂、分叉是否误导目标数量，以及多个闪电是否产生过强闪白。

### 10.3 水波建议规则

P1 水波每 2.0 秒以玩家为中心释放一次，波面半径在 0.45 秒内从 0 增长至 160 px。敌人首次被推进的波面扫到时受到 10 点伤害，并尝试向远离中心的方向击退 30 px；同一次水波只能命中该敌人一次。

检测应覆盖波面本帧推进的范围。敌人之后走进已经扫过的内部区域，不补发伤害。视觉波面结束后可保留 0.25 秒的消散，消散本身不造成伤害。重点观察范围边界、波面的推进、命中时的变形和击退的配合。

### 10.4 视觉与声音的共同规则

重要反馈在实际事件发生时出现。敌方危险信息与玩家轮廓拥有较高显示优先级；自己的尾迹和残留应逐步减弱，避免长期覆盖移动路线。视觉范围要让玩家合理理解有效范围，颜色之外还需要方向、轮廓与运动提供辨识。

同时出现多次攻击时，可以减少碎片和尾迹细节，但保留主体、命中反馈和危险范围。可选镜头震动、伤害数字和声音版本逐项测试，记录其对辨识和感受的实际影响。

## 11 功能组织与性能验证

### 11.1 功能职责

项目建议采用 Godot 的 2D 功能开发；实际引擎版本在创建工程时记录。以下按职责划分模块，具体节点和文件名可在实现时调整。

| 职责 | 管理内容 | 对外提供的信息 |
| --- | --- | --- |
| 游戏流程 | 状态、倒计时、暂停、结算、重开 | 当前状态与结果 |
| 玩家与敌人 | 移动、生命、受击、死亡 | 位置、存活状态、受击事件 |
| 刷怪 | 刷新间隔、数量上限、回收 | 敌人集合与统计 |
| 攻击规则 | 瞄准、弹道、碰撞、伤害、命中编号 | 发射、命中、到期事件 |
| 视觉与声音 | 主体、尾迹、闪光、残留、声音 | 活跃效果数量 |
| 经验与强化 | 掉落、吸取、阈值、候选项 | 等级与参数变化 |
| 试验控制与界面 | 预设、参数、倍率、辅助显示 | 当前试验条件 |

攻击参数和视觉参数使用独立配置。特效播放结束不能成为伤害结算条件；敌人死亡也不能等待死亡动画完成才撤销碰撞。所有短时对象拥有明确的结束或回收条件。

首版可以用简单实例化与回收实现。对象池、空间查询优化和效果合并根据实测瓶颈逐步加入，并保留优化前后的比较数据。

### 11.2 性能观察方法

首轮在实际开发机器、1280 × 720 视口下记录硬件、引擎版本和构建方式。以 60 FPS 为建议观察目标，同时记录平均帧时间、较慢帧和对象数量；在尚未实测前不声称已达标。

先验证生存模式在 150 个敌人以内稳定运行，再在试验模式逐步观察 100、300、500 个敌人的表现。后两档是扩展压力测试，不要求首版保证它们全部达到目标。

比较时分开记录：只运行敌人移动、加入基础攻击、加入命中效果、加入完整尾迹与残留。先定位实际耗时来源，再选择降低粒子数量、缩短残留、减少无效检测或采用对象复用。优化后确认伤害、掉落和范围规则没有改变。

## 13 特效实验流程与记录

### 13.1 每轮实验的步骤

1. 写一个具体问题，例如“较长尾迹是否让火球更容易辨认”。
2. 固定攻击规则、目标布置、镜头、背景、声音和播放倍率。
3. 一次只调整一个主要变量，例如尾迹寿命从 0.12 秒改成 0.22 秒。
4. 单靶重复观察，再测试连续发射和固定靶群。
5. 进入实战，观察遮挡、方向辨识、命中感与性能。
6. 保存条件与观察，给出保留、调整或继续比较的结论。

A/B 是每轮两个版本的比较名称。火球整套视觉 A/B 可用于整体感受比较；要判断哪项变化起作用，应再把主体、尾迹和命中效果逐项拆开比较。

### 13.2 记录模板

每次实验复制以下字段，在项目 docs 下建立单独记录。截图和短视频可以放在对应实验目录，名称与实验编号一致。

| 字段 | 应记录的内容 |
| --- | --- |
| 实验编号与日期 | 例如 FX001；记录实际日期 |
| 问题与预期 | 这次要判断什么，预期会发生什么 |
| 工程与条件 | 引擎、构建版本、视口、背景、目标布置、种子 |
| 固定规则 | 伤害、速度、间隔、寿命、碰撞半径 |
| 改动变量 | A 与 B 的参数，其他条件保持一致 |
| 单次观察 | 发射、飞行、命中、消散的具体差异 |
| 密集观察 | 遮挡、目标辨识、连续触发的感受 |
| 性能观察 | 敌人、弹体、特效数量和帧时间 |
| 结论与下一步 | 保留什么，还需要验证什么 |
| 证据文件 | 截图或视频的项目相对路径 |

### 13.3 第一轮建议

第一轮以“火球尾迹持续时间”为变量。保持主体、发射与命中表现一致，仅比较 0.12 秒和 0.22 秒尾迹。先做单发，再以 1 秒间隔连续发射，然后在实战中观察。记录长尾迹是否增加方向感，是否让已结束的攻击看起来仍有伤害，以及密集画面是否变得模糊。

记录结论时说明适用条件。例如“在 1280 × 720、单靶、1 秒发射间隔下，较长尾迹更易追踪方向；高密度场景仍需缩短”。使用实际观察填写，不能把预期写成已验证结果。

## 14 待验证事项与参考

### 14.1 首轮需要验证的事项

创建工程时记录实际 Godot 版本和渲染方式。第一轮完成后检查五分钟刷怪曲线是否提供合适压力、升级间隔是否过快、火球是否容易命中、A/B 是否有可辨认差异，以及试验面板是否影响观察。

最终美术风格可以在占位原型可用后选择。像素、简化卡通或其他风格会影响轮廓、纹理、透明叠加与亮度处理，确定风格后应重新做同条件比较。

项目后续若转向近战动作、敌方预警或横版躲避，应增加对应测试场景，继续沿用单次观察、控制变量、实战检验和记录结论的流程。
