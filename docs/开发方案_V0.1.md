# xixuegui1010 开发方案 V0.1

对应《游戏功能设计文档 V0.1》的工程实现方案：技术选型、架构、数据结构、场景设计、核心算法与分阶段任务清单。

版本：V0.1　日期：2026年10月11日　依据：docs/游戏功能设计文档_V0.1.md（下称"设计文档"）

本方案中的数值全部来自设计文档的建议初始值，集中放在 `balance/` 目录的 Resource 文件里，改数值不改代码。实现与本方案冲突时，以设计文档的规则为准，并更新本方案。

## 1 技术选型与工程约定

### 1.1 选型

| 项 | 选择 | 说明 |
| --- | --- | --- |
| 引擎 | Godot 4.x 最新稳定版（创建工程时记录具体版本号与渲染后端） | 2D，视口 1280 × 720 |
| 语言 | GDScript | 全部逻辑；不引入 C# |
| 物理引擎 | 不依赖 RigidBody/Area2D 做 gameplay 判定 | 全部命中用手写圆形/扫掠检测，逻辑确定、可控、便于实验；详见 5.3 |
| UI | Godot Control 节点 + 主题 | 中文界面，需自带 CJK 字体 |
| 版本管理 | 本目录内初始化 git 仓库 | 忽略 `.godot/`；`docs/实验记录` 的截图一并入库 |

### 1.5 编码约定

- 类名用 `class_name`，PascalCase；文件名与类名一致（snake_case 文件名）。
- gameplay 代码不使用全局 `randi()/randf()`，一律通过 `Rng` 服务（见 3.4），保证试验种子可控。
- 规则与视觉严格单向依赖：`systems/` 与 `entities/` 只依赖 `common/` 与 `balance/`；`vfx/` 只读运行时数据、发信号，不参与伤害结算。特效结束永远不是结算条件（设计文档 11.1）。
- 所有短时对象（弹体、特效、经验物）必须写明结束条件：命中 / 到期 / 回收 / 合并。
- 每个阶段的验收用例结果记录进 `docs/experiments/` 或里程碑记录。

## 2 总体架构

### 2.1 分层

```
┌ UI 层  main_menu / hud / level_up / pause / results / experiment_panel
│   只读 RunContext 与 EventBus，改状态只通过 Game 的接口
├ 控制层 Game(autoload)   状态机、倒计时、重开清理、time_scale/paused 管理
│   ExperimentController(试验场景节点)   预设/倍率/无敌/参数覆盖/计数
├ 系统层 spawner / projectile_manager / chain / wave / damage_resolver /
│   xp_manager / upgrade_system          每帧推进，只操作实体运行时数据
├ 实体层 player / enemy / fireball / exp_gem   持有自身运行时数据 + 简单自绘
└ 数据层 common/(结构定义) + balance/(数值) + EventBus(信号) + Rng(随机)
```

### 2.2 职责 → 模块映射（对齐设计文档 11.1）

| 设计文档职责 | 本方案模块 |
| --- | --- |
| 游戏流程 | `Game`(autoload) + `ui/` 各界面 |
| 玩家与敌人 | `entities/player`、`entities/enemy` + `DamageResolver` |
| 刷怪 | `systems/spawner.gd`（读 `spawn_curve.tres`） |
| 攻击规则 | `projectile_manager`（火球）、`chain_controller`、`wave_controller`（P1） |

| 经验与强化 | `xp_manager` + `upgrade_system` + `balance/upgrades/` |
| 试验控制与界面 | `ExperimentController` + `ui/experiment_panel` |

### 2.3 状态机（Game autoload）

状态与设计文档 3.2 一致：

```
MAIN_MENU ──开始生存──▶ SURVIVAL ──Esc──▶ PAUSED ──继续──▶ SURVIVAL
   │                     │  ▲                │
   │                     │  └──升级处理完────┤ 重开/返回菜单
   │                     ├──xp 达阈值──▶ LEVEL_UP（pending 处理完回 SURVIVAL）
   │                     ├──死亡或 300s──▶ RESULTS ──重开──▶ SURVIVAL（全新局）
   └──特效试验──▶ EXPERIMENT ──退出──▶ MAIN_MENU
```

实现要点：

- 状态用枚举 + `set_state()` 集中转移，转移处统一处理进入/退出动作（暂停世界、显隐界面）。
- **暂停用 `get_tree().paused = true`**，Arena 及其子节点 `process_mode = PROCESS_MODE_PAUSABLE`，HUD 与各面板 `PROCESS_MODE_ALWAYS`。这样 A07（界面仍可操作）天然成立。
- **慢放用 `Engine.time_scale = 0.25`**（只试验模式用）。注意：`time_scale` 同时缩放 `_process`/`_physics_process` 的 delta 与 Timer，UI 面板要显示"游戏时间 vs 真实时间"时，真实时间用 `PROCESS_MODE_ALWAYS` 节点自己的 delta 累加。
- 同帧既死亡又满 300 秒 → 死亡优先（设计文档 3.2）：结算检查先判 `hp <= 0`。
- 本局结果只生成一次：`RunContext.finished` 标记。

### 2.4 EventBus 信号总表

UI 与特效对 gameplay 的感知全部经信号，反向不引用：

| 信号 | 参数 | 发出者 → 主要订阅者 |
| --- | --- | --- |
| attack_fired | element, attack_id, pos, dir, vfx_profile | 攻击控制器 → vfx/音效 |
| attack_hit | attack_id, target_id, pos, element, killed | DamageResolver → vfx/音效/HUD |
| attack_expired | attack_id, pos, element | 弹体到期 → vfx（轻消散） |
| enemy_spawned / enemy_recycled | enemy | spawner → 试验计数 |
| player_damaged | amount, hp_left | 玩家 → HUD/音效/镜头震动（可选） |
| xp_collected | value, total_xp, level | xp_manager → HUD |
| level_up_pending | pending_count | xp_manager → Game（进 LEVEL_UP） |
| upgrade_chosen | upgrade_id, stacks, summary | upgrade_system → HUD/结算 |
| run_finished | result(胜/负), reason, stats | Game → 结算界面 |
| experiment_setting_changed | 任意试验条件变化 | 试验控制器 → 记录辅助 |

### 3.3 运行时类

```gdscript
# common/run_context.gd —— Game 持有，一局一份；重开 = 重建
class_name RunContext
extends RefCounted

var elapsed: float = 0.0            # 本局生存时间（受暂停停止）
var kills: int = 0
var level: int = 1
var xp: int = 0
var pending_level_ups: int = 0      # 连续升级队列（设计文档 7.2）

var finished: bool = false
var result_win: bool = false
var result_reason: String = ""      # "死亡" / "生存满300秒"

static func xp_threshold(level: int) -> int:
    return 20 + 10 * (level - 1)    # 设计文档 7.2
```

### 3.4 统一随机数服务（autoload/rng.gd）

```gdscript
# autoload/rng.gd
extends Node
var game_rng := RandomNumberGenerator.new()

func reseed(seed_value: int) -> void: game_rng.seed = seed_value
func randf_range(a, b) -> float: return game_rng.randf_range(a, b)
func randi_range(a, b) -> int: return game_rng.randi_range(a, b)
# shuffle/dummy 等按需补
```

试验重置时 `reseed(seed)`；生存模式开局用系统熵做种子（`randi()` 仅此一处可用）。帧率与操作差异会导致实战过程不同，只承诺"同种子同初始局面"（设计文档 9.3）。

### 3.5 关键不变量（写代码时逐条自查）

1. `Enemy.state != ALIVE` 的敌人：不受伤、不碰撞、不掉经验、不计击杀（死亡唯一处理，设计文档 5.3）。
2. 同一 `attack_id` 对同一目标至多结算一次（穿透、试验靶场回血都依赖此条，设计文档 9.1）。
3. 伤害结算先于视觉触发；特效生命周期不参与任何 gameplay 条件。
4. 升级后的参数只影响"之后生成"的攻击（弹体发射时快照 rule/visual）。
5. 暂停/慢放期间：不刷怪、不吸取、不倒计时；恢复不补发（A08）。

试验模式的固定靶也是 `enemy.tscn` 实例 + `is_target = true`（禁移动、命中后回血、不掉经验）。

### 4.3 实体节点形态

- **全部 gameplay 实体用 `Node2D` + 自绘（`_draw` 画占位圆）+ 手动积分移动**，不用 `CharacterBody2D/Area2D`：
  - 场上无墙、无物理交互需求；
  - 命中判定全部是圆形距离/扫掠（见 5.3），手写最直观且确定；
  - 150 个敌人规模下每帧几百次距离判断无压力（设计文档 11.1：首版简单实现，池化与空间划分留作实测瓶颈后优化）。
- 实体脚本持有运行时数据 + `_draw` 占位图形；正式美术确定后仅替换渲染部分。
- 玩家受击闪白 = `modulate` 白色混合 0.08~0.1s；无敌期低频透明度闪烁。

### 4.4 UI 层

```
Main
├── UiLayer (CanvasLayer, PROCESS_MODE_ALWAYS)
```

## 5 核心系统实现要点

### 5.1 移动与镜头

- 输入向量 = 各方向按键组合，`normalized()` 后乘速度；斜向与水平同速（A01 由归一化天然保证）。
- 无输入立即停（无惯性）；位移 = 速度 × delta（delta 来自受 time_scale 影响的 `_process`，慢放自动生效）。
- 相机固定于场地中心（封闭竞技场，全场可见；2026-10 用户改版决策，原为每帧跟随玩家）。
- 刷怪改四面墙内侧随机取点（离墙 24~96px，Brotato 式）；1700px 超距回收保留作安全网（正常对局不会触发）。
- 玩家位移按内区矩形（半场 640x360 - 墙厚 24 - 实体半径）钳制；弹体越内区即消散。

### 5.2 刷怪器（systems/spawner.gd）

```
每帧（SURVIVAL/EXPERIMENT 且未暂停时）：
  elapsed += delta
  phase = 按 elapsed 在 spawn_curve 中查段（段间无缝衔接）
  if elapsed >= next_spawn_time:
      next_spawn_time = elapsed + phase.spawn_interval
      if alive_count < phase.max_alive:
          在镜头边外 ≥64px 生成 1 个敌人（chase_speed = phase.chase_speed，id = ++serial）
      # 达上限：本次跳过，不累积欠账（A15：下一个正常刷新时刻恢复）

每帧遍历敌人：
  dist = enemy.pos.distance_to(player.pos)
  if dist > 1700: 回收（state=RECYCLED、移除，无击杀无经验，设计文档 5.2）
```

- 敌人移动：`pos += (player.pos - pos).normalized() * chase_speed * delta`；允许局部重叠（分离行为留作独立实验）。
- 接触伤害：距离 < 敌半径 + 玩家半径 时尝试伤害；玩家 `iframe_timer > 0` 则跳过。命中重置 `iframe_timer = 0.6`（多敌同帧只扣一次，A04）。

### 5.3 火球：自动瞄准 + 扫掠碰撞（核心算法）

**瞄准**（每帧检查，间隔到时发射）：

```
cooldown -= delta
if cooldown <= 0:
    target = 在存活敌人中找 aim_range 内最近者
             （距离相同取 id 较小者 = 生成序号 tie-break，设计文档 6.1）
    if target 存在:
        发射：attack_id = ++全局序号；dir = (target.pos - player.pos).normalized()
        cooldown += rule.fire_interval        # 注意是 +=，不是 =，避免帧率影响攻速
    else:
        cooldown = 0（无目标不生成火球，下帧继续找，设计文档 6.1）
```

**扫掠碰撞**（解决 A03 高速穿透）：

每帧弹体从 `prev_pos` 移到 `pos`，与所有 ALIVE 敌人做"线段-圆"求交，取最早交点：

```gdscript
# 返回最早命中时间 t ∈ [0,1]，未命中返回 -1
static func segment_hit_t(p0: Vector2, p1: Vector2, c: Vector2, r: float) -> float:
    var d := p1 - p0
    var f := p0 - c
    var a := d.dot(d)
    var b := 2.0 * f.dot(d)
    var cc := f.dot(f) - r * r
    if cc <= 0.0: return 0.0                      # 起点已在圆内
    var disc := b * b - 4.0 * a * cc
    if disc < 0.0 or a == 0.0: return -1.0
    var t := (-b - sqrt(disc)) / (2.0 * a)
    return t if t >= 0.0 and t <= 1.0 else -1.0   # r = rule.hit_radius + enemy.body_radius
```

- 命中判定半径 `r = hit_radius + 敌 body_radius`；多个交点取最小 t（最早，设计文档 6.2）。
- 命中后：若 `pierce` 已用尽 → 结算并销毁弹体；穿透弹把目标记入 `hit_targets`。
- `age >= lifetime` → 到期消散（`attack_expired` 信号，播轻消散，无伤害）。

### 5.4 伤害与死亡管线（systems/damage_resolver.gd）

所有伤害（火球/闪电/水波/接触）走同一入口：

```
apply_damage(target, amount, attack_id):
    1. 守卫：target.state == ALIVE，否则直接返回
    2. 守卫：attack_id 在 target.last_hit_attack_ids 中则返回（试验靶场回血防重）
       （生存模式目标死亡即离场，天然不会重复；穿透弹用弹体自身 hit_targets 去重）
    3. hp -= amount；记录 attack_id；发 enemy_hit（受击闪白 + 音效）
    4. 若 hp <= 0：进入死亡流程（唯一一次）：
       state = DYING；dissolve_timer = 0.18；移出碰撞/受击名单；
       生成经验物（价值 5）；kills += 1；发 enemy_killed
    5. DYING 结束（timer 归零）→ 移除节点
    （试验靶场：第 4 步改为"结算完本次伤害后 hp 恢复满"，回血不复活目标、不触发死亡）
```

顺序固定为"先结算伤害，再触发表现"（设计文档 6.4）。死亡敌人不会因动画未播完而残留碰撞（不变量 3）。

### 5.5 经验与升级

- 经验物静止；玩家距离 < `xp_pickup_radius` → 进入吸取态，以 420 px/s 追玩家；接触（距离 < 玩家半径+4）→ `xp += value` 一次并销毁（A05）。
- 吸取态持续追玩家；暂停/升级/结算时全体停止移动。
- 合并：每 2s 扫描一次，把彼此距离 < 24px 的经验物合并为一个（价值相加，总量守恒，设计文档 7.1）。
- 升级流程：

```
collect(value):
    xp += value
    while xp >= xp_threshold(level):
        xp -= xp_threshold(level); level += 1; pending_level_ups += 1
    if pending_level_ups > 0: 进入 LEVEL_UP 状态
选择一张卡（或满级自动回血 25）后：
    pending_level_ups -= 1
    pending_level_ups > 0 → 刷新三张卡继续选；== 0 → 恢复 SURVIVAL
```

- 候选抽取：过滤 `upgrade_stacks[id] < max_stacks` 的条目 → `Rng.shuffle` → 取前 3（不足则全显示，不重复，A14）。
- 全部满级 → 不显示面板，直接回血 25（满血则 0），等级与经验照常处理。

### 5.6 结算与重开

- 触发：`hp <= 0`（优先）或 `elapsed >= 300`；`finished` 防重复。
- 进入 RESULTS：暂停世界、生成一次结算数据。
- **重开清理清单**（A10，逐项检查）：Arena 下全部敌人/弹体/经验物/特效节点、RunContext 重建（elapsed、kills、level、xp、pending、upgrade_stacks、finished）、Spawner 的 next_spawn_time 与生成序号保留递增但清空存活、弹体全局 attack_id 保留递增、`Engine.time_scale = 1`、试验独有设置（无敌/靶场/倍率）不带入（A13）。

### 5.7 视觉系统（规则-视觉解耦的接口）

- `FireballVisual` 是弹体节点的子节点，只读 `fireball.visual`（VfxProfile）与位置：主体圆 + 可选 wobble 变形、尾迹（`TrailRenderer` 记录最近 N 个点按 `trail_lifetime` 淡出）、命中闪光/余烬由 `FxLayer` 经 `attack_hit` 信号生成。
- **A/B 切换**：只改 `ProjectileManager.current_visual`，之后发射的弹体快照新 profile；已生成弹体持旧 profile 到结束（设计文档 9.3）。
- 声音：发射/命中/击杀/受击四个占位音；同类命中音加 0.05s 最小播放间隔防叠加；A/B 比较期共用同一套声音（设计文档 6.4）。

### 5.8 试验模式（ExperimentController）

- 预设三选（单靶 / 固定靶群 10~50 / 实战追击），共用 arena 与攻击规则，独立配置：靶场不掉经验不升级、靶子命中结算后回满血。
- 播放控制：暂停（tree.paused）/ 0.25× / 1×（Engine.time_scale）；面板节点 PROCESS_MODE_ALWAYS，暂停时仍可点击调参；界面同时显示游戏时间与真实时间。
- 单次触发：世界运行中按空格 → 以固定发射点朝最近靶（单靶/靶群）或最近敌（实战）发射一发；暂停时按钮与空格无效并提示。连续触发 = 开关注射间隔自动发射。
- 参数面板分两页签：**攻击规则**（伤害/间隔/速度/寿命/碰撞半径）与**视觉表现**（主体/尾迹/命中/消散/亮度）；改规则页时界面标红提示"本轮已改变玩法条件"（设计文档 9.2）。面板数值直接写 `rule` 副本，重置时从 .tres 恢复。
- 重置：清场（同 5.6 清理清单）→ `Rng.reseed(seed)` → 重建预设场景。
- 辅助：深/浅背景（Ground 换配色）、灰度（Fx 与弹体层挂 desaturate shader 或统一 modulate 处理，用于检查轮廓辨识）、碰撞半径显示（DebugDraw 画所有弹体 hit_radius 与实体 body_radius 圆）。面板可收起，收起后仍显示暂停/倍率/无敌状态。
- 计数：当前敌人数、弹体数、活跃特效数、FPS、平均帧时间（`Engine.get_frames_per_second()` + `_process` 内测 ms）。

### 5.9 性能与池化

- 首版直接 `instantiate/queue_free`；`FxLayer` 与 `ProjectileManager` 各自维护计数供面板显示。
- 实测瓶颈后再加：弹体/经验物/特效对象池（`acquire()/release()` 接口）、敌人网格分区（均匀 cell 查询）。每轮优化前后记录同条件帧时间对比（设计文档 11.2），并回归验收用例确认规则未变。

- `RunContext.xp_threshold`：L=1→20，L=2→30，L=3→40。
- `segment_hit_t`：正穿/掠过/远距未中/起点在内/超帧长距离各一例。
- 升级候选抽取：池被 shuffle 且不重复、不足 3 张返回全量、全满返回空。
- 刷怪段查询：边界值 0 / 60 / 180 / 300。
- 连锁目标选择（Phase 4）：距离并列、已死目标跳过、上限截断。

## 10 决策记录

| 决策 | 理由 |
| --- | --- |
| 不用物理引擎做 gameplay 判定 | 场上无墙；扫掠需求（A03）手写更直接；确定性与可复现性对实验项目更重要 |
| 实体 = Node2D + 手绘 + 手动积分 | 首版规模（≤150 敌）够用；性能优化有明确升级路径（池化/网格/MultiMesh） |
| 规则/视觉 = 两套 Resource + 发射时快照 | 设计文档核心学习目标；A/B 与"只影响新生成"语义天然成立 |
| EventBus 单向事件 | UI 与特效不反向耦合 gameplay；特效永不参与结算 |
| 暂停用 tree.paused、慢放用 time_scale | 两者正交，A07/A08 语义清晰；面板 ALWAYS 保可用 |
| 数值全部入 balance/*.tres | 改平衡不动代码；试验面板改副本、重置还原 |

## 11 实施记录（2026-10-11，V0.1 完成后更新）

M0~M2（Phase 0~3）已全部实现并验收：113 项自动化测试通过（`tests/test_runner.tscn`，headless），真实渲染截图验收通过（`tests/screenshot_runner.tscn` → `docs/screenshots/`）。与原方案的偏差：

1. **CJK 字体**：未导入字体文件，改用 `SystemFont`（微软雅黑回退链）+ `ThemeDB.fallback_font`，在 `ui/main.gd` 启动时设置。仅限本机（Windows）开发；若要跨平台分发需随包附带 OFL 字体。
2. **UI 全部代码构建**（原方案即有此倾向，正式确认）：所有面板在 `_ready` 中构建，未写 .tscn；后续可迁移为场景+主题。
3. **实体无 `_process`**：一切 gameplay 更新集中在 `Arena._step`（玩家/敌人/弹体/经验/特效全部 tick），相机跟随与地面绘制属于表现仍用引擎 `_process`。测试因此能用 `step_manual(固定步长)` 完全确定地驱动世界。
4. **测试跑法**：`tests/test_runner.tscn` 场景方式（autoload 齐全）而非 `--script`；集成测试通过手动步进覆盖 A01~A15 中可自动化的部分，A16 的"可辨认性"为人工观察项（FX001 模板已建）。
5. **音效**：无音频资产，运行时用 `AudioStreamWAV` 合成四个占位音（发射/命中/击杀/受击），命中音 0.05s 节流。
6. 试验单靶预设位置从 (420,0) 调整为 (280,0)、靶群半径 380→300：避开右侧面板遮挡（截图验收发现）。
